# 部署与自动化验收

目标是让接收者用自己的Python、依赖和模型账户运行完整代码，不依赖作者的Codex、钥匙串、绝对路径或历史文件。服务仍仅供本机浏览器使用，不是公网多用户服务。

## 1. 接收者首次部署

解压源码包，在LauraPhysics目录中使用Python 3.10或更新版本。Windows将python3换成py。

```sh
python3 scripts/setup_environment.py --venv ../runtime
```

Mac/Linux：

```sh
export LAURAPHYSICS_PYTHON="$(pwd)/../runtime/bin/python3"
export LAURAPHYSICS_DISABLE_LEGACY_CONFIG=1
python3 scripts/run_web.py --check
python3 scripts/run_web.py --open
```

Windows PowerShell：

```powershell
$env:LAURAPHYSICS_PYTHON = (Resolve-Path ..\runtime\Scripts\python.exe).Path
$env:LAURAPHYSICS_DISABLE_LEGACY_CONFIG = '1'
py scripts/run_web.py --check
py scripts/run_web.py --open
```

访问127.0.0.1:8895。第一次安装需要网络，之后人工选题/组卷/PDF导出不需模型账户；AI需要接收者自行配置可用文字和图片模型。Windows/Linux密钥通过LAURAPHYSICS_OPEN_API_KEY环境变量传入，网页密钥框留空。不要把真实密钥发给别人或写进包中。

## 2. 一次性自动化复测

在上一步环境里运行（Windows改用runtime/Scripts/python.exe）：

```sh
../runtime/bin/python3 scripts/run_tests.py --output ../acceptance-results --install
```

会安装测试依赖与Chromium，输出JUnit、结果JSON、日志、进程内覆盖率与网页/PDF证据。缺浏览器、测试失败或跳过均不能认定完整验收通过。测试仅用独立数据目录和明确模拟模型，不调用真实外部API，不代表手写识别准确率；记录中的Token是模拟协议字段，不是服务商计费数据。

## 3. 本地审核包

```sh
python3 scripts/prepare_release.py --output ../release-review
```

默认不含Mac专用vendor、运行环境、密钥、历史与学生数据。包内release-manifest.json列出版本和逐文件SHA-256；包外发布包检查.json列出整个ZIP校验值。先核对包完整性，再部署。传递依赖通过requirements-tested.txt安装，不靠复制已安装目录。

正式代码许可证已由负责人确认为AGPL-3.0-only，题库与依赖许可仍单独适用。当前推荐GitHub安装方式见[新Mac部署指南](MAC_DEPLOYMENT.md)。本地打包命令只生成文件，不代表已向GitHub发布或已完成第二台实体机验收。

## 4. 必须区分的证据

- 同一台Mac的新目录/新环境：能证明摆脱既有安装和路径依赖，不能证明Windows/Linux实体机兼容。
- 非本机平台wheel下载成功：证明指定平台有锁定依赖的二进制分发，不能证明安装启动和界面正常。
- 模拟平台分支与模型协议：证明相应代码行为，不证明该操作系统或真实模型能力。
- 实体第二台电脑：必须实际安装、启动、跑测试并带回版本/环境/日志/生成PDF，才能标记实机通过。
- 无桌面Linux：通过浏览器下载PDF/ZIP，不保证远程桌面或公网访问；当前服务器拒绝非localhost绑定。

## 5. 另一台电脑回传清单

提供系统/架构、Python版本、environment_check输出、acceptance-results/test-result.json、junit.xml、首屏与组卷/批改截图、生成PDF；密钥、真实学生身份和私有试卷不回传。建议先用教师自写匿名样例做组卷、上传、暂停继续、复核和批量导出。真实视觉模型需另做经过授权的样本对照验收。
